BrainCareDZ — Schéma de la base de données (PostgreSQL)

BrainCareDZ est une application de gestion de cabinet de psychologie et neurofeedback en Algérie. Elle gère patients, rendez-vous (Psy/Coach), packs de séances, comptes-rendus, paiements, factures B2B, dépenses et évaluations. Stack : Next.js 16 + TypeScript + Tailwind (frontend), Express.js + PostgreSQL (backend), auth JWT, rôles Admin/Psy/Coach.

Description du schéma

Base BrainCare (PostgreSQL). Chaque table possède un id UUID généré par gen_random_uuid() sauf indication contraire. Les clés étrangères sont ON DELETE CASCADE sauf cas particuliers : invoices.created_by, payments.created_by et expenses.created_by en SET NULL pour préserver l'audit, payments.patient_id en RESTRICT, invoices.company_id et waiting_list.practitioner_id en RESTRICT pour empêcher les suppressions dangereuses. Les tables de liaison practitioner_services, appointment_patients, patient_motifs et patient_pack_shares matérialisent des relations Many-to-Many. La table patient_outcomes conserve l'historique des évaluations (amélioration perçue, satisfaction) — les colonnes d'évaluation dupliquées ont été supprimées de patients. La colonne patients.practitioner_id est un cache maintenu par un trigger (trg_sync_patient_practitioner) synchronisé avec le dernier RDV non annulé. Le solde patients.balance est recalculé automatiquement par des triggers sur payments, patient_pack_usages et appointments. Les rôles utilisateurs sont admin, psy et coach. La table calendar_settings a une contrainte CHECK sur calendar_role. session_notes a une contrainte UNIQUE sur appointment_patient_id.
